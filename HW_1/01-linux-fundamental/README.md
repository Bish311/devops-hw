## Task 1: Soft Link vs Hard Link

### Conceptual Overview
- **Inode:** A data structure on a Linux filesystem that stores metadata about a file (file size, permissions, owner, timestamps, and block pointers) except its file name.
- **Hard Link:** A direct directory pointer to an existing inode on the same filesystem. Creating a hard link increments the inode's link count. If the original file is deleted, the data remains accessible through the hard link until all links pointing to that inode are removed.
- **Soft Link (Symbolic Link / Symlink):** A separate small file with its own unique inode that stores the path string to the target file. If the original file is deleted or moved, the soft link points to a non-existent path and becomes broken (dangling pointer).

### Comparison Matrix

| Feature | Hard Link | Soft Link (Symlink) |
|---|---|---|
| **Inode** | Shares the identical inode of the target file | Has its own independent inode |
| **Filesystem Boundary** | Cannot span across different filesystems or partitions | Can link files across different filesystems and mounts |
| **Directory Linking** | Not permitted for regular users (prevents filesystem loops) | Fully supported for directories |
| **Deletion Behavior** | Data remains intact until link count drops to 0 | Link breaks immediately if target file is deleted or renamed |
| **Creation Command** | `ln <target> <link_name>` | `ln -s <target> <link_name>` |

### Practical Execution

```bash
# Step 1: Create a test file
echo "Database configuration authored by Bishwayan" > config.env

# Step 2: Create hard link and soft link
ln config.env config_hard.env
ln -s config.env config_soft.env

# Step 3: Inspect inodes and link counts
ls -li config*
# Output example:
# 1048576 -rw-r--r-- 2 bish bish 45 Sep 11 10:00 config.env
# 1048576 -rw-r--r-- 2 bish bish 45 Sep 11 10:00 config_hard.env
# 1048577 lrwxrwxrwx 1 bish bish 10 Sep 11 10:01 config_soft.env -> config.env

# Step 4: Remove original file
rm config.env

# Step 5: Verify contents
cat config_hard.env
# Output: Database configuration authored by Bishwayan

cat config_soft.env
# Output: cat: config_soft.env: No such file or directory
```

### Interview Questions & Answers
- **Q: What happens to a hard link if the original file is deleted?**
  - **A:** The data remains accessible. Deleting a file decrements the inode link count by 1. The filesystem blocks are only freed when the link count reaches 0 and no running process holds an open file descriptor to it.
- **Q: Why can hard links not span across multiple disk partitions?**
  - **A:** Inode numbers are unique only within a single filesystem. Different partitions maintain separate inode tables; referencing an inode across partitions would lead to data corruption or incorrect file mappings.

## Task 2: adduser vs useradd

### Key Differences

| Property | `useradd` | `adduser` |
|---|---|---|
| **Binary Type** | Compiled low-level ELF binary utility (part of `shadow-utils`) | High-level interactive Perl script wrapper around `useradd` |
| **Home Directory** | Does not create `/home/<username>` by default unless `-m` is specified | Creates `/home/<username>` automatically from `/etc/skel` |
| **Password Setup** | Leaves account locked without password unless passed via `-p` or followed by `passwd` | Interactively prompts for UNIX password and profile metadata |
| **Default Shell** | Defaults to `/bin/sh` or system default unless `-s` is specified | Defaults to `/bin/bash` or configuration in `/etc/adduser.conf` |
| **Ubuntu Preference** | Used for automated scripts and system service accounts | Preferred for interactive human user provisioning on Ubuntu/Debian |

### Practical Usage

```bash
# 1. Recommended interactive user creation on Ubuntu:
sudo adduser Bishwayan

# 2. Scripted/Automated non-interactive user creation:
sudo useradd -m -s /bin/bash -c "Bishwayan DevOps Account" Bish
sudo passwd Bish
```

## Task 3: System and Service Logging with journalctl

`journalctl` is the command-line utility for querying logs generated by `systemd-journald`.

### Critical Commands

```bash
# View all logs in reverse chronological order (most recent first)
journalctl -r

# Follow logs in real-time (like tail -f)
journalctl -f

# Filter logs for a specific systemd service unit (e.g., ssh, nginx, docker)
journalctl -u docker.service -n 50 --no-pager

# Filter logs by priority level (emerg, alert, crit, err, warning, notice, info, debug)
journalctl -p err..emerg

# Filter logs for the current boot session
journalctl -b

# Filter logs within a specific time window
journalctl --since "2026-09-10 00:00:00" --until "2026-09-11 12:00:00"

# Check disk space occupied by journal logs and clean older logs
journalctl --disk-usage
sudo journalctl --vacuum-size=500M
```

## Task 4: Essential Linux Administration Commands

| Category | Command | Purpose & Usage |
|---|---|---|
| **System Info** | `uname -r` | Prints kernel release version |
| | `uptime` | Shows how long system has been running and load averages |
| | `hostname -I` | Displays IP addresses assigned to host interfaces |
| **Disk & Memory** | `df -h` | Human-readable disk space usage by mounted filesystem |
| | `du -sh <path>` | Summary disk usage for a specific folder |

| | `top` / `htop` | Interactive real-time process monitoring |
| | `kill -9 <PID>` | Forces immediate process termination via SIGKILL |
| **Networking** | `ss -tulpn` | Lists active listening TCP and UDP sockets with process IDs |
| | `curl -I <url>` | Fetches HTTP response headers only |

### Observation on Task 3 (`journalctl` in Containers)
In containerized sandbox environments (e.g., lightweight runner containers where custom entrypoints like `cinit` run as PID 1 instead of `systemd`), the `systemd-journald` logging daemon is not initialized. Consequently, `journalctl` correctly reports `No journal files were found.` On a bare-metal Linux machine or complete virtual machine running `systemd`, `journalctl` connects to `/run/log/journal/` or `/var/log/journal/` to yield persistent service logs.
